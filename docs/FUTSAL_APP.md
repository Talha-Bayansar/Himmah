# Himmah Futsal app and identity

The owner approved a separately installable Futsal experience on 20 October 2026, explicitly retaining Himmah identity. Futsal uses the same leaf, forest green `#12382f`, lime `#def19e`, warm canvas, typography, accessible controls and accounts. A leaf-and-shield icon, club crests, pitch markings, illustrated jerseys and player cards give it football character. No real photographs or third-party club branding is used.

## Separate installation

Open `/futsal` on the existing HTTPS origin. Futsal manifests use the distinct stable ID `/futsal`, start URL `/futsal` and scope prefix `/futsal`. Hub keeps ID `/`, start `/hub` and its existing icons. Both can be offered as separate installations on browsers that support manifest identity. A custom domain is not required or provisioned. OS/browser support decides native installation, cookie sharing and splash behavior; separate installed windows may require sign-in using the same account.

Futsal has localized manifests, 192/512/maskable icons, a 180px Apple icon and 44 iOS startup images generated by the existing asset script. The familiar Himmah leaf sits inside a football-style shield. Route-aware server metadata and client updates select the matching manifest/title/icons/splashes, including after language changes or navigating from Hub. Use Install Himmah Futsal in the season list/clubhouse/profile, or the browser's Add to Home Screen flow. To install alongside Hub, open the Futsal URL in the phone’s Safari/Chrome browser; install controls are hidden inside standalone app windows. Physical Android/iOS installation is not established by automated checks.

The launcher stays inside Futsal while signing in/verifying. A verified account with one organization from a complete bounded first page opens that organization's Futsal area. Multiple/partial memberships use the existing paginated chooser; it never fetches every organization just to launch. No private account or selected season is persisted in browser storage. Organization switching preserves the app. `/futsal/profile` contains language, installation and confirmed sign-out; existing accounts/authentication remain shared. Scope changes do not grant access or create accounts, organizations or seasons.

One existing root service worker serves both app identities. Public cache v4 includes both sets of install icons and retains the same private-data exclusion, network-only authenticated navigation, no offline mutations, normal update activation and opt-in generic push policy. Existing Hub push subscriptions and delivery scheduling are unchanged; game-specific push alerts are not added.

## Game navigation and real pages

Assigned participants see their activated competitions, then open a clubhouse. Owners/admins can enter an active club from the season list and retain separate season administration through Manage. The fixed game navigation has Clubhouse, Squads, Competition and Training; a saved-result Matchday page is linked from the latest fixture. All pages are independent reloadable routes under `/futsal/:organizationId/seasons/:seasonId/` (`clubhouse`, `squad`, `competition`, `training`, `matchday`). A validated `club` search parameter preserves the viewed club after reload; the participant's assigned entry is the default. The API checks assignment independently of that display preference.

Clubhouse shows saved team ratings, played matches, league position, next scheduled event, latest results and the first five player cards. Squads show saved attributes, ratings and reserves. Competition shows league standings or knockout round/winner references, schedule and saved results. Training explains the locked conversion and displays saved improvements. Matchday offers a short score reveal of the latest saved fixture, with replay and reduced-motion support. Revealing/replaying is local presentation only: it never calls a mutation or recomputes an outcome.

Game administration remains on the existing setup/settings/entries/Play routes. Activation and due-event processing stay explicit organizer commands; this redesign does not add automatic jobs, lineup choices, fictional squads or editable ratings.

## Privacy and data

The existing participant detail API now includes the saved public fixture plan and that participant's assigned entry ID. It still strips person identifiers from football state and returns no engagement allocations. Participant training is a new read-only endpoint `/api/organizations/:org/futsal/play/:season/training`, authorized by current active account link, non-archived roster person, organization/season assignment and prepared season status. It returns only that person's saved growth rows, removes person IDs and never exposes peer awards, attendance, quiz results, reasons or allocation maps. Staff use the existing authorized audit API.

Season lists and training histories retain bounded cursor/infinite fetching. Season squads/fixtures are existing bounded aggregates. There is no new database migration, service, domain, billing entitlement or game-engine rule change. Match/training receipts, locked rules, saved results and Hub point balances remain intact.

## Verification

Automated checks cover separate manifest identities/scopes, icon/splash dimensions, existing Hub manifests, own-club defaults, immutable reveal behavior, participant training redaction/current-access checks and all existing gameplay/PWA/auth regressions. Production-asset browser checks use intercepted synthetic APIs to exercise all four mode/format combinations, all five game pages, real navigation/reload, zero gameplay writes during reveal, profile language metadata, launcher states and EN/NL/TR phone/tablet layouts. They do not create production fixture data or send pushes.

Game navigation keeps the selected club in the validated URL search parameter across tabs and reloads. Organizer game views honor both season cancellation and the current game API cancellation flag: cancelled seasons retain historical results with a localized notice and do not show upcoming-play or completion prompts. Participant cancellation access policy remains unchanged.
